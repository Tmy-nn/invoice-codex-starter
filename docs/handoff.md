# 導入・引き渡し手順

## 受け取り時

1. 自社が管理するGitHubアカウントで公開ページの **Use this template → Create a new repository** を選び、自社所有の新しいリポジトリを作る。担当者の個人アカウントにだけ依存しない所有・アクセス権を決める。
2. PCへクローンし、`README.md` の架空10件を実行する。
3. `python -m unittest discover -s tests -v` と架空200件を実行する。
4. `data/` と `output/` の保存先、バックアップ、アクセス権、保存期間を社内で定める。

## 実データへ進める前に確定すること

| 項目 | 確認内容 |
|---|---|
| 実行PC | WindowsかMacか、Pythonの導入方法と更新担当 |
| 入力Excel | 列名、顧客ID、請求区分、対象件数、欠番の扱い |
| 請求書 | 正式な発行者、税率・税額・端数処理、登録番号、振込先、支払期限、顧客別例外 |
| メール | 使用するメールソフト、下書き取り込み、添付・宛先の確認手順 |
| AIの利用 | 契約プラン、顧客情報をAIへ渡せる範囲、アクセス権、ログの扱い |
| 保存 | PDFと電子取引データの保存ルール、バックアップと復元方法 |

実データへ移る際には、この公開版のサンプル請求書をそのまま使わず、確定した様式と税計算を実装・検証します。架空データで1件、10件、実際の対象件数の照合を通した後、担当者が実運用開始を判断してください。メール送信は担当者が手動で行います。

## 他の業務

請求書の手順が安定したら、`docs/roadmap.md` の例から自社に必要な業務を選び、一業務ずつ追加します。各業務に入力、出力、確認者、再実行方法、データ保存先を決めます。
