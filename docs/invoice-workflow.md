# 請求書ワークフロー

## 対象

入力はExcelの1行を1請求先として扱う。顧客ID、請求先名、メールアドレス、税込金額を読み、指定した請求月のPDFと `.eml` を作る。入力額をそのまま表示し、税額計算や端数処理は行わない。請求書の正式な様式・税率・登録番号・振込先は利用企業が確定する。サンプルの値を実際の請求に流用しない。

## 状態と担当

| 段階 | 出力 | 確認する人 |
|---|---|---|
| 入力確認 | 件数、重複ID、空欄、金額形式の検査結果 | 請求担当者 |
| 生成 | 月別の新しい実行フォルダにPDF・EML・manifestを保存 | 請求担当者 |
| 照合 | 顧客ID・宛先・請求月・入力した税込額を原本と比較 | 請求担当者 |
| 送信 | メールソフトで宛先・添付を再確認して手動送信 | 権限を持つ担当者 |

## 運用上の確認点

1. 本番データを使う前に、顧客ごとの請求区分、税率、端数処理、適格請求書の記載事項を確定し、未実装の計算と表示を追加する。
2. 生成前にExcelを別名で保全する。スクリプトは入力ブックを変更しない。
3. `--expected-count` に対象件数を指定し、欠番や重複を検出する。
4. `COMPLETE.txt` があることを確認する。`INCOMPLETE.txt` があれば生成結果を使用せず、原因を直して再実行する。
5. `manifest.csv` の各行と `summary.json` の件数・合計額を請求元データと照合する。PDFを数件目視し、宛先・文字化け・ページ収まりを確認する。
6. EMLは下書きファイルであり、メールソフトへの取り込みと送信は担当者が行う。
7. 出力フォルダはGit管理外。保存期間・バックアップ・アクセス権は自社のルールで決める。

## 現時点の境界

この公開版は架空データによる試作。税務上の判断、請求の承認、送信、電子取引データの保存運用を自動化しない。本番投入時には実際の請求書様式と入力列を確認し、対象件数の試験結果を担当者が承認する。
